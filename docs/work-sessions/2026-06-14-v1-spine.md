## Key decisions during build

- Outbound is a single **reconciling relay** (not a thread-per-target with cross-module wiring): it reads
  `RoutingState.active_targets()` each pass, so a disconnected target drops from consumption
  automatically — no router→relay coupling.
- Surface-aware send unified via `get_channel` (cache) → `fetch_channel` (covers DM/channel/thread by id)
  rather than branching on a source field the `Outbound` model doesn't carry.
- `in_reply_to` threading is best-effort: a non-Discord id (Redis stream id) falls back to a plain send.
- Hermes/discord.py reach (adapter/client/loop extraction, command context) is behind mockable helpers;
  exact internals are confirmed at the acceptance gate against the live `mimir-engineer` profile (KTD5).
